**Input**: Design documents from `specs/002-dashboard-redesign/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/](./contracts/) ([routes.md](./contracts/routes.md), [spec-md-structure.md](./contracts/spec-md-structure.md), [search-index.md](./contracts/search-index.md)), [quickstart.md](./quickstart.md)

**Tests**: REQUIRED. Constitution §IV (unit tests for all code) and §V (E2E coverage of every user story and major requirement) are non-negotiable. Each logic task names its unit test file and ships the module and its tests together. Each story phase has its own Playwright suite. E2E test names MUST start with the story and requirement ids they cover, for example `US2 FR-024 shows the tooltip 500 ms after the pointer enters` (DEVELOPMENT.md rule, §V traceability).

**Organization**: Tasks are grouped by user story so each story can be implemented and tested as its own increment. Story order follows the spec priorities: US1 (P1) → US2, US3, US4 (P2) → US5, US6 (P3).

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: The user story the task belongs to (US1–US6)
- All paths are relative to the repository root

## Conventions that apply to every task

- Plain JavaScript ES modules with JSDoc, Node.js ≥ 22, no TypeScript, no UI framework and no bundler (research D1). The runtime dependency list stays `markdown-it` only.
- All server HTML is produced with the `html` tagged template from `src/render/html.js`; only trusted fragments go through `raw()` (001 R4). Rendered documents and task text never run scripts: `markdown-it` with raw HTML off (001 FR-024).
- **CSP is unchanged** (`default-src 'self'; style-src 'self'; script-src 'self'; img-src 'self' data:`): no element may carry a `style="…"` attribute, no inline `<script>`, no `eval`/`new Function`. Data-driven widths use the `w-pct-<0..100>` classes (research D6); SVG presentation attributes (`stroke-dasharray`, `stroke`) are allowed; positions computed in the browser are set through the CSSOM (`el.style.left = …`).
- **Without JavaScript** every page stays readable and navigable, and the tree, phases, task rows, clarification sessions, stories and the mobile menu open and close (`<details>`). Controls that only work with scripts (theme switch, order, depth, filters, search entry, map mode, expand all, detail panel) are rendered with the `hidden` attribute and un-hidden by their module's `init` (FR-053).
- **Browser modules** live in `src/client/`, are served as `assets/<name>.js`, and follow one contract (research D2, contracts/routes.md "Browser modules"): `export function init(root, deps)` — idempotent, called on load and after every live swap — and, when the module holds page-local state, `export function save(root) → object`, read back via `init(root, { state, … })`. `deps` injects `document`, `window`, `storage`, `setTimeout`/`clearTimeout`, `fetch`, `navigator` so the module is unit-testable. Every `localStorage` access goes through `src/client/prefs.js`.
- **Unit tests** use `node:test` + `node:assert/strict`, live in `tests/unit/`, and never touch the real file system, network or a browser (§IV). Client modules are tested against `happy-dom` (`new Window()` per test, research D11) in files named `tests/unit/client-<module>.test.js`; layout-dependent code is tested with stubbed `getBoundingClientRect` values. Existing hand-written fakes (`tests/unit/fake-fs.js`, `tests/unit/fake-reader.js`) stay.
- Colors exist once, as `light-dark()` tokens on `:root` in `src/styles/input.css` (research D3); values come from `mockups/001-first-redesign/DESIGN_HANDOFF.md`'s token table plus the rose blocked tokens of research D15. Utilities reference tokens (`bg-(--surface)`); no Tailwind `dark:` variant.
- Icons come only from `src/render/icons.js` (research D5). Fonts come only from `dist/fonts/` (research D4).
- Ordering rules exist only in `src/model/ranks.js`; proportional widths only via `shares()` in `src/model/shares.js`; task states keep 001's rules in `src/model/task-state.js` (§III).
- The target project is never written (001 FR-006). Only `src/project/reader.js` reads input files; only `src/build/build.js` writes output files.
- Every user-visible change adds a line under `## [Unreleased]` in `CHANGELOG.md` (§VI, research D18). The version in `package.json` stays `1.0.0`.
- Fixture counts quoted in tasks come from `tests/fixtures/projects/README.md` and quickstart.md (`mixed`: 4 features, 65 tasks, 40 done; `002-beta` T018 depends on the open T011).
